# 客户端接口与服务验证

客户端使用 `POST /api/v1/xhs/notes/generate`，旧的 `/report` 保留原有字符串报告契约。请求为 `multipart/form-data`：

当前 `/generate` 将全部图片和完整 `idea_text` 放入一次视觉请求，同时生成逐图观察和自由稿件，不用固定模板覆盖。来源、引用、事实、排版和发布长度等编辑问题保留完整草稿，通过 `review_warnings` 提示核对；JSON/schema 损坏、图片 ID 不完整及绝对资源超限仍失败。不静默截断、不追加模型修复请求。用户要求决定体裁、篇幅和语气，明确提供的背景可保留。

2026-10-28两次用户请求中，模型已分别用21.3165秒和19.1716秒完成，但旧本地渲染 `ValueError` 被统一转换为502。旧日志未保留具体规则或原始稿，不能确切定位各次原因；本轮已将编辑问题改为可见警示。当前 Python **631项**、Flutter **32项**测试通过，本机假上游10个全链路场景覆盖软警示和硬失败，未追加真实模型请求。历史154.700秒、7.2986秒及后续菊花对照均不是当前耗时保证，详情见[生成速度优化](生成速度优化.md)。

- `idea_text`：去除首尾空白后 1～2000 字符。
- `images`：重复字段，按客户端选图顺序上传 1～20 张静态图片。每张最多 10 MiB，总计最多 50 MiB。
- `X-API-Key`：配置了 `APP_API_KEYS` 时必填。这是本服务访问凭证，不能把 `APP_LLM_API_KEY` 放在客户端。

成功响应：

```json
{
  "code": 0,
  "message": "ok",
  "request_id": "...",
  "data": {
    "title": "标题",
    "content": "正文",
    "tags": ["生活记录"],
    "image_order": ["img_0", "img_1"],
    "report": "标题、正文等的兼容文本摘要",
    "is_demo": false,
    "review_warnings": []
  }
}
```

`img_0` 是第一张上传图片，依次递增。快速链路保留上传顺序，`image_order` 始终包含所有上传 ID 且不重复，客户端据此排列本地图片。图片保留在客户端；服务端临时图会在请求完成或取消时删除，接口不返回下载地址或临时路径。

`review_warnings` 是可选字符串数组，默认 `[]`，后端去重后最多12条。新版客户端在预览页明确展示，提示待核对来源、事实或待调整格式；警示不附加到复制正文或兼容 `report`，没有警示也不代表事实已验证。无效背景摘录不作为依据。旧客户端仍可解析基本稿件，但需要更新才能显示这些警示。

发布目标为标题最多20字符、正文与复制时附带的话题最多1000字符。超过目标时仍返回原稿并提示精简；绝对资源上限为标题200、正文8000字符、话题最多16项且每项100字符。它们是接收草稿的安全上限，不是平台发布额度。正文和标签分开返回，服务不会静默截断。

新接口出错时使用 HTTP 400（意图/数量不合法）、413（体积或像素超限）、415（视频、损坏图或不支持的图片）、429（生成槽已满）、502（上游失败或 JSON/schema、图片 ID 等硬校验失败）、503（缺少模型密钥）、504（生成超时），响应为 `{"code": HTTP状态码, "message": "...", "request_id": "..."}`。来源、事实、排版或发布目标问题不再单独导致502。字段缺失遵循 FastAPI 的 422 `detail`。429 携带 `Retry-After: 10`。不要自动重试生成 POST，避免重复调用模型。请求 ID 同时放在响应头 `X-Request-ID`。

图片通过 Pillow 实际解码验证，支持 JPEG、PNG、WebP、静态 GIF、BMP、单页 TIFF 与 HEIC/HEIF（pillow-heif）。拒绝视频、动图、多帧图片、超出 4000 万像素的图片。服务端按 EXIF 自动转正，长边压缩至 1024 像素，标准化为 JPEG 或透明 PNG，仅供模型分析；客户端发布仍使用本地原图。

## 本地启动

```sh
uv sync --frozen --extra dev
cp .env.example .env
# 编辑.env填写APP_LLM_API_KEY
uv run --frozen uvicorn app.main:app --host 0.0.0.0 --port 8072
```

`uv.lock` 固定依赖，CrewAI 固定在已离线验证的 1.15.32。需要 Python 3.11 以上；本次实际使用 Python 3.13.13。模型名读取 `.env` 中的 `APP_LLM_MODEL` 与 `APP_LLM_IMAGE_MODEL`，不再硬编码带日期的模型版本。当前默认 `qwen-plus` / `qwen3-vl-plus`，实际可用性以账号权限与地域为准。

无密钥时可用 `APP_XHS_DEMO_MODE=true` 启动本地联调，所有图片校验仍真实执行，返回明确的演示文案与 `is_demo=true`。它不会调用模型；`APP_ENV=production` 时禁止此模式。配置密钥后关闭演示模式再生成真实笔记。

## 并发、超时和成本

快速生成和完整报告都放在独立 Python 子进程中，快速子进程不加载 CrewAI。API 主进程异步等待，健康检查不会被同步代码阻塞。取消或达到总超时会终止生成进程，然后清理图片。杀死进程不能撤销上游已经收到并处理的模型请求，其已发生费用仍可能计入账单。

默认每个 API 进程同时处理 2 次生成，额外请求直接返回 429，不无限排队。快速链路每次仅一个模型请求，因此一个 API 进程最多2个快速模型请求同时运行；完整报告每个子进程内模型并发最多3。部署多个 Uvicorn worker / 副本时上限按数量相乘，这不是全局限额。总硬超时600秒，单次模型请求默认120秒。快速链路关闭重试、重定向、格式修复调用与文本模型回退；`APP_LLM_RETRY_COUNT` 只影响旧报告链路。

原始多智能体链路在 `/report` 保留：视觉分析 → 修图建议 → 策略/文案/SEO，最少包含 `2 × 图片数 + 5` 个任务。客户端 `/generate` 一次携带全部图片，输出预算随图数增加，不通过省略图片提速。20张图的请求字节、视觉输入和输出仍大于单图，耗时与费用不能假设相同。独立进程保留少量启动和内存开销，适合当前本地/小规模服务；需要高吞吐时可改用专用工作进程与任务队列。
