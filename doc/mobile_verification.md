## 已完成的功能

`flutter_client/` 是可独立构建的 Android / iOS Flutter 工程。相册仅提供图片单选和多选；支持删除、预览和调整顺序。用户输入创作想法后以 multipart 上传至 Python 服务，服务返回独立的标题、正文、标签和图片排列。最终页保留选图，允许修改文案、分别复制标题/正文、复制整篇并分享图片。

Android 使用标准图像 Intent，优先小红书，无法接收时回退系统选择器；iOS 使用系统分享面板，用户选择小红书。只传图片附件，文案通过剪贴板手动粘贴。分享交接和发布成功是不同的状态，应用不自动点击发布。

## 后端修复与性能边界

修复新版 CrewAI 导致服务无法导入、硬编码模型配置、文件重名覆盖、非图片上传未拦截、上传无限制、图片压缩阻塞事件循环、超时后任务继续占用与临时图片未可靠清理等问题。真实调用还发现原看图工具可能被模型跳过；现已改成每个视觉/编辑任务首轮强制发送对应图片，离线验证图片字节、模型和并发隔离。新增生成长度约束和不虚构事实的提示，客户端超长编辑只警示、不截断。新 `/generate` 返回结构化结果，原 `/report` 保留兼容。Docker 构建缺少源文件的问题已修复，实际构建 wheel 并验证 YAML 配置和子进程入口已入包。

完整 Crew 流程在受控子进程运行：每 API 进程最多 2 个上传/生成，单生成内最多 3 个模型请求并发，总超时 600 秒，客户端断开后终止子进程并清理临时图。多 Uvicorn worker 或副本会使这个并发上限相乘。上游已收到的模型请求及费用无法撤销。

离线上游的完整子进程端到端测试：单图 4.032 秒；生成期间 89 次健康检查全部 200，p50 2.809 ms、最大 26.669 ms。这证明本机任务隔离和主进程响应正常，不能代替外部模型时延或吞吐量测试。原多智能体流程最少需要 `2 × 图片数 + 5` 个任务，图像工具与结构化修复还可能增加调用；建议先用 1～4 张图片验证效果与费用。更多细节见 [客户端接口与服务验证](客户端接口与服务验证.md)。

修复后的真实复测使用同一张三文鱼餐盘照片：两次 `qwen3-vl-plus` 请求的图片 SHA-256 和本地规范化图片一致，五次文本请求使用 `qwen-plus`；总计 27,988 tokens。154 次并发健康检查全部 200，p50 2.599 ms，最大 31.912 ms。耗时主要来自多轮外部模型调用，不能把离线 4 秒当成真实生成速度。

文案质量仍需人工核对：本次正确识别了主要食材，但仍扩写了未提供的制作方式、味道和饱腹体验。提示词进一步禁止此类推断，界面保留发布前核对提示；不能宣称事实约束已经完全可靠，也不能把该次稿件当作可直接发布的事实样例。没有进行第三次付费验证。小红书真机发布器的接收效果同样仍需实际设备验收。

## 复现

后端：`uv run --frozen pytest tests/ -q`。客户端：进入 `flutter_client`，运行 `flutter test --no-pub` 与 `dart analyze`。完整启动、演示服务和模拟器测试命令见 [客户端 README](../flutter_client/README.md)。

真实模型验证需在 `.env` 填写 `APP_LLM_API_KEY`，关闭演示模式，启动新的服务进程。当前密钥已配置，已完成最初的一次调用和用户单独授权的一次复测。不要将模型密钥写进 Flutter；客户端设置中的 API Key 是服务鉴权用的 `APP_API_KEYS`。

本轮结束时，8072 端口已启动非演示服务，`/health/live` 返回200。同一局域网的手机可在客户端服务设置中填写 `http://电脑当前局域网IP:8072`（须替换为实际 IP，验证机地址未公开）；IP 变化或电脑重启后需重新确认地址/启动服务。最终 Android 调试包为 `flutter_client/build/app/outputs/flutter-apk/app-debug.apk`，入口是正式 `lib/main.dart`，不包含自动化测试入口。
